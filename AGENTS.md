# AGENTS.md

This file provides guidance to the AI agent when working with code in this repository.

## Workflow rules

- **One logical change = one commit, and commit it before starting the next one.** A "logical change" is something a reviewer can describe in one sentence (one fix, one feature, one doc truth-correction) — that is the commit unit. Never bundle two independent changes into one commit just because they are sitting in the working tree together, and never hold changes back to be "efficient": batch commits hide which change broke what, and the whole point of committing as you go is that each step is independently verified and independently revertable.
- Gates before each commit, then commit immediately: the change must be fmt/clippy/test-clean on its own (see *Build / test / lint*), with its own conventional-commit message and scope: `feat(android): ...`, `fix(core): ...`, `docs: ...`. Stage files by name, so an unrelated dirty file can't ride along. Never push unless explicitly asked.
- Update the docs a change touches (README.md, CONTRIBUTING.md, docs/, `man/`) in that change's commit — the doc fix travels with the code it describes, but a doc that describes a *different* change gets its own commit.
- **Never commit anything sensitive, and verify the staged set before every push/commit — not just the file you edited.** No private keys, TLS/QUIC certs, pairing PINs, trust stores, tokens, `.env` files, real device identifiers/MACs/tailnet addresses, core dumps, logs, or database files. No agent- or editor-local state (`.qoder/settings.json`, `.qoder/sessions/`, `~/` — the stray SDK dir). Where the secrets actually live: `state_dir()` = `$XDG_STATE_HOME/pocketdesk` (`pairing.pin`, `trusted_devices.json`, `certs/`), i.e. **outside this repo** — never copy one in, and if a test needs one, generate a throwaway. Config examples ship as placeholders only (`.env.example`'s `JWT_SECRET` is a fake and must stay that way). Stage by name (never `git add -A`/`.`), run `git diff --cached --name-only` plus a `git diff --cached` skim as the last gate, and if a secret was ever committed treat the push as the leak: say so immediately rather than quietly rewriting history.
- Each item gets a milestone-level entry at the top of `docs/status-history.md`, in its own commit or with its docs. Keep *Current Status* below to a few lines: it is read by every session, so it says where things stand and points to the rest, never the journal itself.

## Build / test / lint

- Rust workspace members: `core`, `server`, `desktop` (the Pocketdesk egui app; its Linux tray is a StatusNotifierItem over D-Bus, so it needs no GTK there), `android/bridge`, `spike/iroh` (edition 2024; the spike is a throwaway research crate, `publish = false`).
- Kotlin unit tests: `cd android && ./gradlew testDebugUnitTest` (JVM tests under `app/src/test`, started with the pairing-link work).
- The bridge builds `pocketdesk-core` with `default-features = false, features = ["client"]`. Every change in `core` must compile and pass clippy under BOTH profiles:
  - `cargo clippy --workspace --all-targets -- -D warnings`
  - `cargo clippy -p pocketdesk-core --no-default-features --features client -- -D warnings`
- Tests: `cargo test --workspace`.
- Kotlin app: `cd android && ./gradlew assembleDebug`. Android SDK (Platform 37, Build-Tools 37) and Gradle wrapper are configured and buildable on host; the NDKs here are r27/r28 (CI and F-Droid pin r29 in `android/bridge/ndk-version`). The APK needs the bridge `.so` in `android/app/src/main/jniLibs/<abi>/` first (gitignored): `POCKETDESK_RUST_TOOLCHAIN=stable-x86_64-pc-windows-gnu sh android/bridge/build-android.sh` on this box (it pins Rust in `android/bridge/rust-toolchain-version`; the box's default host is MSVC, which cannot link here, so a repo-wide `rust-toolchain.toml` would break it). A quick debug build: `cd android/bridge && cargo ndk -t arm64-v8a -o ../app/src/main/jniLibs build`. See docs/development-setup.md §5.

- Windows host (branch `feat/windows-host`): the server and core build on `x86_64-pc-windows-gnu` (MinGW via WinLibs — this dev box has MSVC tools but **no Windows SDK**, so MSVC cannot link here). Windows gates: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --exclude pocketdesk-android-bridge --exclude iroh-spike -- -D warnings`, `cargo test --workspace --exclude pocketdesk-android-bridge --exclude iroh-spike`; live Windows tests are `#[ignore]`d (docs/development-setup.md §4 lists them). The Linux gates cannot be run from Windows (PipeWire/FFmpeg/ring need a Linux C toolchain) — every Windows-branch commit that touches shared code owes a Linux gate run before merge.

## Gotchas

- `android/bridge` is a cdylib producing `libpocketdesk_android_bridge.so`, loaded by `RustCore.kt`. JNI exports must match the Kotlin package exactly: `Java_dev_pocketdesk_android_bridge_<Class>_<method>`.
- Edition 2024 requires `#[unsafe(no_mangle)]`, not `#[no_mangle]`.
- `main` is rustfmt- and clippy-clean as of 2026-09-24, so **`cargo fmt --all -- --check` and `cargo clippy --workspace --all-targets -- -D warnings` are gates, not baselines** — keep them green and do not add exceptions to hold them down (the pre-existing "7-error baseline" was a *build stop* in `core/src/streaming/{capture,capture_x11,streamer}.rs` that hid every lint behind it; it is gone). The durable trap from the debt era: a whitespace-only line makes rustfmt **abort before reporting anything** (internal error "left behind trailing whitespace" — it happened at `server/src/v2_multiplexer.rs:102`), so never read a fmt run that printed nothing as clean; check its exit status. Format or fix only files your change actually touches; never reformat wholesale.
- `cargo clippy --workspace` unifies features across members, so it catches client+server cfg conflicts that per-package checks miss. Run it after changing feature gates in `core`.
- Server runtime needs Linux desktop libs (PipeWire, Wayland, xdg-desktop-portal); the server *build* also links system FFmpeg (`ffmpeg-next` under the `encode` feature) — install the libav* dev packages, not just the `ffmpeg` binary.
- iroh lives behind the NON-DEFAULT `wan` feature (core); the Android bridge builds core with `client,wan`. WAN code paths are only compiled/tested with an explicit `--features wan` (e.g. `cargo test -p pocketdesk-core --features wan`).
- **Features say *what*, `cfg(target_os)` says *how*.** Linux-only crates (ashpd, pipewire, wayland-*, x11rb, evdev, zbus, ffmpeg-next) live in `[target.'cfg(target_os = "linux")'.dependencies]`; `windows` is under `cfg(windows)`. A feature such as `capture` names both with `dep:`, and only the one that exists for the target activates. Off-Linux code that names a Linux crate fails to compile on Windows, not on Linux — so a Linux-only change can still break the Windows build. Note `target_os = "linux"` is **false on Android**; the bridge takes the non-Linux arms of shared code (e.g. `get_local_ips` uses `if-addrs` there).
- Windows build traps already paid for: `iroh-relay` is `crate-type = ["lib","cdylib"]`, and MinGW's ld auto-exports aws-lc's symbols into that DLL past the 65,535-ordinal PE limit — `.cargo/config.toml` passes `--exclude-libs,ALL`; CMake 4 refuses Opus's old `cmake_minimum_required` without `CMAKE_POLICY_VERSION_MINIMUM=3.5` (same file). rustc/clippy 1.99 (this box) deprecate `fetch_update` and flag `chunks_exact_mut`/`double_must_use` that older toolchains don't — write the portable form, never the 1.99-only replacement.
- Windows runtime traps: the clipboard must be opened with an owner window or `EmptyClipboard` leaves it ownerless and the data is dropped; enigo's `Key::LMenu` is VK_LMENU (left **Alt**) on Windows, not the Menu key; toasts for an unpackaged exe need an AppUserModelID registered under `HKCU\Software\Classes\AppUserModelId`; never call a system tool by bare name (`taskkill`, `netsh`, `schtasks`) — resolve it under `System32`.
- **Never run power, lock or server-stop actions on the user's Windows dev box** (user instruction): tests that would sleep, shut down, lock or stop the server stay `#[ignore]`d and are listed as owed device checks.
- Hyprland 0.56's socket1 IPC write dispatchers (`dispatch`/`keyword`/`setoption`) are broken upstream (hyprwm/Hyprland#16224) — never use them. All window/workspace actions ride the uinput injection path (Super+N hotkeys, etc.). Read-side `j/…` queries work fine.
- VAAPI works on this box — the old "VAAPI init fails here" gotcha was WRONG. This is a hybrid Intel-iGPU + NVIDIA-dGPU laptop: `/dev/dri/renderD128` is the NVIDIA card (no VA driver → `Failed to initialise VAAPI connection`) and the Intel **iHD** driver that actually encodes H.264/HEVC lives on `/dev/dri/renderD129`. Both the in-process (`encoder_vaapi.rs`, C4) and the sidecar encoder now pick the node by trying each `/dev/dri/renderD*` (override with `POCKETDESK_VAAPI_DEVICE`) instead of assuming `renderD128`. NVENC is the genuinely-blocked path: the 580.178.04 driver predates FFmpeg 9's NVENC API-13 requirement (13.1), so NVENC stays on the verified sidecar and any NVENC-specific work is untestable here.
- Every UI/transport feature is gated on `assembleDebug` + `lintDebug` (Kotlin) and both clippy profiles + `cargo test --workspace` (Rust), but **almost nothing has been run on a real device** — treat on-device behavior as unverified unless the bullet says otherwise. `docs/` carries the on-device verification checklist (commit 4469e83).
- API 37's android.jar removed `MediaCodecInfo.isDecoder()` and `MediaCodec.create{Encoder,Decoder}ByString` — HEAD's C1 codec-probe Kotlin broke when the SDK updated (android-37.2); use `createDecoderByType`/`createEncoderByType` and instantiate-probe instead of `isDecoder` scans.
- Licensing rule (from the R4 research): RustDesk (AGPL-3.0) and Sunshine (GPL-3.0) contribute architecture/technique only, never code; scrcpy (Apache-2.0) and IronRDP (MIT/Apache-2.0) are the sole code-borrowable projects.
- Working tree routinely carries the user's parallel in-progress edits across core/server/bridge — never revert, stash, or reformat uncommitted work that isn't yours.
