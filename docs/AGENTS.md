# AGENTS.md

Guidance for AI agents working in this repository. Keep it short: it loads into every session.

## Workflow rules

- One logical change per commit (one fix, feature or doc correction), committed before the next. Each commit passes the gates on its own and uses a conventional message with a scope (`feat(android): ...`, `fix(core): ...`, `docs: ...`). Never push unless asked.
- A change updates the docs it touches (README.md, CONTRIBUTING.md, docs/, `man/`) in the same commit.
- Never commit anything sensitive: keys, certs, PINs, trust stores, tokens, `.env`, real device ids, MACs or addresses, logs, dumps, editor state. Secrets live in `state_dir()` outside the repo; tests generate throwaways. Stage files by name (never `git add -A`/`.`) and read `git diff --cached` before every commit. If a secret was ever pushed, say so at once instead of rewriting history.
- Clear throwaways as the last step of the run that made them: a throwaway server keeps only `state/` and `config/`; `%TEMP%` `pd-*`/`ll-*`/`bridge-*` go after tests; a merged PR's worktree, `target/` and `android/app/build` go.
- Each item gets an entry at the top of `docs/status-history.md`. Current Status below stays a few lines.

## Build / test / lint

- Workspace: `core`, `server`, `desktop` (egui app), `android/bridge` (cdylib for the Android app, builds core with `default-features = false, features = ["client"]`), `spike/iroh`.
- Gates: `cargo fmt --all -- --check`; `cargo clippy --workspace --all-targets -- -D warnings`; `cargo clippy -p pocketdesk-core --no-default-features --features client -- -D warnings`; `cargo test --workspace`. On Windows add `--exclude pocketdesk-android-bridge --exclude iroh-spike`. WAN paths need `--features wan`.
- Android: `cd android && ./gradlew assembleDebug lintDebug testDebugUnitTest`. The APK needs the bridge `.so` in `android/app/src/main/jniLibs/<abi>/` first; build it with `POCKETDESK_RUST_TOOLCHAIN=stable-x86_64-pc-windows-gnu sh android/bridge/build-android.sh` on the Windows box (docs/development-setup.md §5).
- The Windows box builds with MinGW (`x86_64-pc-windows-gnu`; no Windows SDK). Linux gates can't run there: shared-code changes owe a Linux run (the Arch laptop or CI).

## Gotchas (the full list is docs/gotchas.md; read the parts for the area you touch)

- Never run power, lock or server-stop actions on the owner's Windows PC; tests that would are `#[ignore]`d and listed as owed device checks. Never run test binaries or servers there at all (each new exe path pops a firewall prompt): Linux gates and live tests run on the Arch laptop (`ssh arch`) or in CI.
- `core` must pass clippy under both profiles (workspace, and `--no-default-features --features client` for the bridge). fmt and clippy are gates, not baselines; a whitespace-only line makes rustfmt abort silently, so check its exit status.
- Features say *what*, `cfg(target_os)` says *how*; Linux-only crates live under `cfg(target_os = "linux")`, which is false on Android. Off-Linux code naming a Linux crate breaks the Windows build.
- Edition 2024 needs `#[unsafe(no_mangle)]`; JNI exports must match `Java_dev_pocketdesk_android_bridge_<Class>_<method>`.
- Hyprland 0.56's socket1 write dispatchers are broken upstream (hyprwm/Hyprland#16224); read queries and `output`/`eval` work.
- Licensing: RustDesk and Sunshine are inspiration only; code may come only from scrcpy and IronRDP.
- Never revert, stash or reformat uncommitted work that isn't yours.
