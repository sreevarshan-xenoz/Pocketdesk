# Control channel packets

Generated by `pocketdesk capabilities --packets` from the plugins this build registers; `server/tests/packets_doc.rs` fails while this file differs. Do not edit it by hand.

Each packet is one line of JSON on the control channel (`docs/protocol-spec.md`). *Phone → computer* packets are acted on only for a paired phone with the permission shown; an unpaired phone may send only `kdeconnect.pair` and `kdeconnect.pocketdesk.pair`, and a packet it lacks the permission for is dropped (a folder fetch or an audio request is answered as refused). *Computer → phone* packets are what the computer pushes or answers with. A computer announces both lists in its identity packet (`incomingCapabilities`, `outgoingCapabilities`), which is how a client learns what it offers.
