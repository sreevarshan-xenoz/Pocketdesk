# Gotchas

Traps already paid for. AGENTS.md keeps only the ones every change needs; the rest live here.

- `android/bridge` is a cdylib producing `libpocketdesk_android_bridge.so`, loaded by `RustCore.kt`. JNI exports must match the Kotlin package exactly: `Java_dev_pocketdesk_android_bridge_<Class>_<method>`.
- Edition 2024 requires `#[unsafe(no_mangle)]`, not `#[no_mangle]`.
- `main` is rustfmt- and clippy-clean as of 2026-09-24, so **`cargo fmt --all -- --check` and `cargo clippy --workspace --all-targets -- -D warnings` are gates, not baselines** — keep them green and do not add exceptions to hold them down (the pre-existing "7-error baseline" was a *build stop* in `core/src/streaming/{capture,capture_x11,streamer}.rs` that hid every lint behind it; it is gone). The durable trap from the debt era: a whitespace-only line makes rustfmt **abort before reporting anything** (internal error "left behind trailing whitespace" — it happened at `server/src/v2_multiplexer.rs:102`), so never read a fmt run that printed nothing as clean; check its exit status. Format or fix only files your change actually touches; never reformat wholesale.
- `cargo clippy --workspace` unifies features across members, so it catches client+server cfg conflicts that per-package checks miss. Run it after changing feature gates in `core`.
- Server runtime needs Linux desktop libs (PipeWire, Wayland, xdg-desktop-portal); the server *build* also links system FFmpeg (`ffmpeg-next` under the `encode` feature) — install the libav* dev packages, not just the `ffmpeg` binary.
- iroh lives behind the NON-DEFAULT `wan` feature (core); the Android bridge builds core with `client,wan`. WAN code paths are only compiled/tested with an explicit `--features wan` (e.g. `cargo test -p pocketdesk-core --features wan`).
- **Features say *what*, `cfg(target_os)` says *how*.** Linux-only crates (ashpd, pipewire, wayland-*, x11rb, evdev, zbus, ffmpeg-next) live in `[target.'cfg(target_os = "linux")'.dependencies]`; `windows` is under `cfg(windows)`. A feature such as `capture` names both with `dep:`, and only the one that exists for the target activates. Off-Linux code that names a Linux crate fails to compile on Windows, not on Linux — so a Linux-only change can still break the Windows build. Note `target_os = "linux"` is **false on Android**; the bridge takes the non-Linux arms of shared code (e.g. `get_local_ips` uses `if-addrs` there).
- Windows build traps already paid for: `iroh-relay` is `crate-type = ["lib","cdylib"]`, and MinGW's ld auto-exports aws-lc's symbols into that DLL past the 65,535-ordinal PE limit — `.cargo/config.toml` passes `--exclude-libs,ALL`; CMake 4 refuses Opus's old `cmake_minimum_required` without `CMAKE_POLICY_VERSION_MINIMUM=3.5` (same file). rustc/clippy 1.99 (this box) deprecate `fetch_update` and flag `chunks_exact_mut`/`double_must_use` that older toolchains don't — write the portable form, never the 1.99-only replacement.
- Windows runtime traps: the clipboard must be opened with an owner window or `EmptyClipboard` leaves it ownerless and the data is dropped; enigo's `Key::LMenu` is VK_LMENU (left **Alt**) on Windows, not the Menu key; toasts for an unpackaged exe need an AppUserModelID registered under `HKCU\Software\Classes\AppUserModelId`; never call a system tool by bare name (`taskkill`, `netsh`, `schtasks`) — resolve it under `System32`.
- **Never run power, lock or server-stop actions on the user's Windows dev box** (user instruction): tests that would sleep, shut down, lock or stop the server stay `#[ignore]`d and are listed as owed device checks.
- Hyprland 0.56's socket1 IPC write dispatchers (`dispatch`/`keyword`/`setoption`) are broken upstream (hyprwm/Hyprland#16224) — never use them. All window/workspace actions ride the uinput injection path (Super+N hotkeys, etc.). Read-side `j/…` queries work fine. What does work on 0.56 is `eval`, real Lua: `eval hl.dispatch(hl.dsp.window.move({ monitor = "…", follow = false, window = "address:0x…" }))` moves a window to a screen, `hl.dsp.window.fullscreen_state({ internal = 2, client = 0, … })` fills the screen on the compositor's side while the program is told nothing, and `hl.dsp.window.move({ workspace = … })` puts it back (window lending, `server/src/lend_window.rs`); `eval` answers `ok` even for a window that is not there or a dispatcher that does nothing (only a Lua error says `error:`), so read `j/clients` to see what happened. A moved floating window loses its place; set it again with `resize`/`move` and `exact = true`. Hyprland starts only on a real or nested backend: `AQ_BACKENDS=headless` alone fails (`CBackend::create() failed`), and a nested one needs a host compositor that offers `xdg_wm_base` version 6, which Sway 1.12's wlroots does not (the nested Hyprland aborts with `invalid version for global xdg_wm_base`).
- VAAPI works on the Linux laptop (a hybrid Intel-iGPU + NVIDIA-dGPU machine); the old "VAAPI init fails here" gotcha was wrong. Which `/dev/dri/renderD*` node is the Intel card and which the NVIDIA one varies with the drivers loaded and the boot (it has been both ways round: check `/sys/class/drm/renderD*/device/driver`), so never assume a node: the in-process (`encoder_vaapi.rs`, C4) and the sidecar encoders try each `renderD*` in turn (`POCKETDESK_VAAPI_DEVICE` overrides), and the NVIDIA node, with no VA driver, falls through to the next rung ("No usable encoding profile found"). NVENC needs NVIDIA's proprietary driver at an NVENC API FFmpeg accepts; on nouveau, or a proprietary driver older than FFmpeg's NVENC requirement, the probe logs "driver rejects it" and does not select NVENC, so NVENC work (and the C3 clock pin) is untestable there. The in-process VA-API encoder converts BGRA to NV12 on the card (`scale_vaapi` on a BGR0 surface, phase 1c) and falls back, with one warning, to `sws_scale` on the processor where the driver or FFmpeg cannot; `POCKETDESK_VAAPI_CPU_CONVERT=1` forces the processor path for A/B timing.
- Every UI/transport feature is gated on `assembleDebug` + `lintDebug` (Kotlin) and both clippy profiles + `cargo test --workspace` (Rust), but **almost nothing has been run on a real device** — treat on-device behavior as unverified unless the bullet says otherwise. `docs/` carries the on-device verification checklist (commit 4469e83).
- API 37's android.jar removed `MediaCodecInfo.isDecoder()` and `MediaCodec.create{Encoder,Decoder}ByString` — HEAD's C1 codec-probe Kotlin broke when the SDK updated (android-37.2); use `createDecoderByType`/`createEncoderByType` and instantiate-probe instead of `isDecoder` scans.
- Licensing rule (from the R4 research): RustDesk (AGPL-3.0) and Sunshine (GPL-3.0) contribute architecture/technique only, never code; scrcpy (Apache-2.0) and IronRDP (MIT/Apache-2.0) are the sole code-borrowable projects.
- **A borrowed window's view never falls back to the other computer's own screen.** `ComputerAsk::View`'s `borrow` shows one window of another computer on a hidden screen it lends; when the lend fails (the switch off, the window closed since the list, the four screens used) the view ends with the reason, because `monitor` would show whatever the owner has open there. The same goes for its close: it never locks that computer (`say_closing` and `would_lock` skip a borrowed window), and the Hide/mic/fit/screen controls are not drawn for it. The viewer asks `lend` again each time the view dials after a drop (the host answers with the same screen while the window is lent, or lends afresh after the host gave it back), so a link drop that returned the window at the host does not leave the view on a gone screen.
- Window titles are personal: `list` carries them, `windows_there` in `computers.json` holds them while the app's picker is open (the app asks for it to be cleared when the picker closes or the page is left, the server drops one nobody asked for again within 60 s (an open picker asks every 30 s) and any at its start, and unpairing drops it), and nothing logs them. Keep it so: log counts, never titles.
- Working tree routinely carries the user's parallel in-progress edits across core/server/bridge — never revert, stash, or reformat uncommitted work that isn't yours.
- A swap that waits for the display (vsync) holds the event-loop thread, and one thread draws every window of the app (the main window, a computer's screen, the casts): on Wayland the wait is Mesa's wait for the surface's frame callback, which a window the compositor is not showing (another workspace, fully under another window) never gets, so that window's swap blocked for ever and every window of the app stopped (found in the phase 1d work; reproduced in a headless sway). So on Wayland the swap never waits (`frame_pacing::swap_waits`), and `frame_pacing` holds each window to twice the display's refresh instead (without it a spinner drew 14,500 frames a second, a whole core). winit 0.30 reports no occlusion on Wayland and eframe 0.36 never calls `pre_present_notify`, so a window that is not shown keeps drawing its pictures (the same cost as shown); real frame-callback pacing, and no drawing of a hidden window, wait for eframe to ask for the callback. egui also answers every immediate `request_repaint` with a second frame "to settle", which a waiting swap hid: ask for a picture's frame with a delay (`request_repaint_after_for`, 1 us), which asks once.
- **The input-capture portal never says a button was held as the pointer crossed.** It says a barrier was hit and then streams libei's events, so a window drag past the edge (`shared_input/drag_window.rs`) is read from the end of the drag: the left button, and the modifier a compositor moves a window with, going up on the other computer with no press of them seen in that visit (`Evidence`). Read as the drag ends, the window is offered then, not as the pointer crosses; a trigger that waits on the modifier gives it 500 ms after the button. Sway has no input-capture portal, so on Sway the pick and the return work (live-tested in a headless Sway) but no edge is watched; Hyprland 0.56's capture with a button held is unchecked. A window with `border csd` in Sway's tree may be one that never asked to draw its own decorations: `border csd` is then refused, and `sway_all` lets that one command pass or the return stops and leaves the window lent.
