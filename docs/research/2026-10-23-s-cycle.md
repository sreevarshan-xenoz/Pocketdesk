R found nothing new worth building that people asked for, and finished what was half-done. Meanwhile the owed device checks kept growing.

`docs/owed-checks.md` lists 562 open items that can run here: this Windows box and a test phone, without touching the owner's power, lock or input. The phone is now the OPPO (CPH2359); the A71 the older ones were written for is gone. Next come 122 for a Linux desktop and 93 by hand or eye.

## How each batch runs

**Running each item:**
- Each open "here" item of its sections is run as written, against a throwaway server, by `adb` and `uiautomator`.
- `scripts/device_checks.py` is extended where an item will be run again.
- An item that would need input on this computer, its power or its lock is moved to the right list instead.
- So is one that needs another device, with the reason.

**Recording the results:**
- A pass is ticked in the checklist with the date and what was seen.
- A failure becomes a fix, one PR each, with its test, a fresh review and the gates, as any item.
- An item that is stale (the feature changed since) is rewritten to what is true now, or removed with its reason.
- Each batch is one PR of checklist changes, plus the fix PRs it found; its status entry counts passed, fixed, moved and stale.

**Checked:** `docs/owed-checks.md` regenerated after each batch, the "here" count falling.

## Not in it

- **Power, lock or server stop on this box:** never run here, the owner's rule.
- **Input reaching this computer's desktop:** needs the owner's OK, so those wait.
- **A SIM, a second phone or computer, other networks, other hardware:** what this box does not have.
