# The AZ cycle (2026-10-26), after AY

AX made a removed or moved computer's link, wakes and notification picks follow it on the phone. AY made an unpaired phone's standing follow it on the computer. This cycle takes up what AX left as lower: the three things on the phone that still name a computer by its address alone, never by the paired id `HostStore` keeps. A move (O3), a removal, or a different computer later saved at the old address can each leave them pointing at the wrong one. Each is fixed as its own PR (Phase R). The plan is removed when the cycle ends.

| # | Item | Where | Checkable here |
|---|---|---|---|
| AZ1 | Pinned shortcuts are matched to a saved computer by address alone (`Shortcuts.refresh`, `takeShortcut`, Direct Share's `shortcutHost`). A move disables a still-saved computer's pinned shortcut ("no longer saved"). A different computer paired later at a removed one's address re-enables the old shortcut, contrary to the comment above that code. Its Connect then opens a session on the new computer and its Direct Share sends there, under the old computer's name. Each pinned shortcut is tied to the paired id it was made for: it follows a move and stays off for another computer | `android/app` | Yes (unit tests; the OPPO by adb) |
| AZ2 | The deck widget keeps its list `for` an address (`DeckWidgetPlan.keeps`). A computer saved at the address of the one whose list it shows inherits that list: its buttons, pressed, go to the new computer, which runs its own action when it has the same label at that index. A removal with no computer left keeps the list on disk. The list is kept for the paired id too | `android/app` | Yes (unit tests) |
| AZ3 | The bridge's name cache (`peer_names.rs`: a computer's own name, whether it answers notifications and takes live cards) is keyed by address and never cleared. A computer at a removed one's address that gives no name in its handshake is saved under the removed one's name for good, and its answering flags are the old one's. Remove and a move forget the address's entry | `android/bridge`, `android/app` | Yes (unit tests) |
| AZ4 | A fourth sweep of the whole device-check runner on main, after AX and AY, long checks too | `scripts` | Yes (the OPPO) |
| AZ5… | A fix for each FAIL found, as its own PR | | Yes |

## Not in it

- The certificate pin: Remove already forgets it, so a different computer at the old address must pair before anything reaches it. None of the three items can reach a computer the phone never paired.
- "Pocketdesk control", the owner-gated list, and the 0.7.0 tag.
