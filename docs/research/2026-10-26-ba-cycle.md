# The BA cycle (2026-10-26), after AZ

AY made an unpaired phone's standing follow it on the computer. This cycle audits the same for the owner's other computers (2f), each way: a computer forgotten here (Unpair on the Computers page), and this computer unpaired on another (that one's Devices page or `pocketdesk unpair`). The audit found that the per-packet gate holds once a device is unpaired, but what it already started does not stop, and a Forget can quietly not happen. Each item is its own PR (Phase R). The plan is removed when the cycle ends.

| # | Item | Where | Checkable here |
|---|---|---|---|
| BA1 | A transfer under way when its device is unpaired runs to its end. The device's standing is checked only as a transfer's route is set up (`share::route`, `transfer_tls`), so a phone or computer unpaired mid-file still finishes receiving a file this computer offered, or writing one into its Downloads. A transfer stops, cancelled as the app's Cancel does, once its device is no longer let in | `server` | Yes (unit tests; the runner, a long transfer and an unpair on the throwaway) |
| BA2 | An unpaired device's connection stays open. Nothing closes it, and iroh's keepalive holds an internet-road link for good: another computer that was unpaired here keeps sending its clipboard over it (dropped at the gate), and still shows this one as linked, its sends waiting out their retries. With pairing required, a device's connections close as it is unpaired | `server` | Yes (unit tests; the runner) |
| BA3 | The Computers page's Unpair asks the server, but unlike Pair it is offered with the server stopped. It says "Unpaired here", the request expires unread (120 s), and the link comes back at the next start, with its clipboard and its offers. An unreadable `computers.json` uses the request up the same way. Unpair waits for the server as Pair does, and a Forget that cannot be done is said | `desktop`, `server` | Yes (unit tests; UI tests) |
| BA4… | A fix for each FAIL found, as its own PR | | Yes |

## Not in it

- A forgotten computer still trusting this one on its own side: by design, said in the app; its owner unpairs it there.
- A computer refused by the other redialing it every five minutes: it shows "refused" until forgotten here.
- A CLI to forget a computer: a feature, not a fix.
- "Pocketdesk control", the owner-gated list, and the 0.7.0 tag.
